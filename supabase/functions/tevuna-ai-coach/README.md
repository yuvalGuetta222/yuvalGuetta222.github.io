# תבונה AI - הפעלה ותפעול

שירות ה-AI מופעל ב-Supabase Edge Function בשם `tevuna-ai-coach` (JWT חובה), ומקבל קריאות רק משני משתמשי משק הבית המורשים באמצעות Supabase Auth ו-RLS.

## הפעלת מודל אמיתי

מומלץ להגדיר ב-Supabase Dashboard > Edge Functions > Secrets משתנה בשם `OPENAI_API_KEY` עם מפתח API מורשה של OpenAI.

**לעולם אין להזין את המפתח בקוד GitHub, בקובץ HTML, בכתובת URL או בשיחה.** השימוש ב-OpenAI API מחויב בנפרד ממנוי ChatGPT ותלוי בתנאי החשבון.

כאפשרות זמנית, אפשר לפתוח את מסך "יועץ AI" באתר ולהזין מפתח API בשדה הפרטי. הוא נשמר רק בזיכרון הדף הנוכחי ונשלח דרך HTTPS לפונקציית Supabase בעת בקשה יזומה בלבד; אינו נשמר ב-localStorage או במסד הנתונים.

אם לא הוגדר מפתח בשרת ולא הוזן מפתח זמני, יוצג מצב "טרם חובר" ולא יוצגו תשובות כוזבות של AI.

## אילו נתונים נשלחים למודל?

רק סיכומים מחושבים על ידי שירות Supabase לאחר אימות המשתמש וההרשאה למשק הבית: סך הוצאות נטו לאחר זיכויים, קטגוריות, מסגרות תקציב, הכנסות שהתקבלו, נתונים מצטברים של החודש הקודם ודגלי אי-התאמה בין דוחות. **לא נשלחים דוחות המקור, עסקאות בודדות, שמות בתי עסק, שמות משתמשים, מספרי כרטיס, כתובות מייל או מסמכים.** כל לחיצה מפעילה בקשה נפרדת; אין סריקה אוטומטית ברקע.

המודל `gpt-4o-mini` מפרש נתונים. החישובים הם דטרמיניסטיים במסד הנתונים; אי אפשר לערוך או למחוק נתונים דרך הצ'אט.

## אבטחה ומגבלות

- Function deployment: `verify_jwt: true`, אימות Auth + חברות ב-`tevuna_members`, שאילתות דרך RLS.
- מכסה: 25 בקשות לכל משתמש לכל יום (שעון ישראל), מנוהלת בצד השרת.
- מפתח OpenAI לא נכתב ללוגים או לתשובות.
- אין שמירת היסטוריית שיחות או תשובות AI במסד הנתונים.
- מסמכים חסרים ופערי התאמה מוצגים כאזהרות; ה-AI לא ממציא עסקאות כדי לסגור פער.
- ה-AI לא מחשב יתרת בנק ואינו מכניס התחייבויות קבועות ללא טיפול בהתאמות לחיובי אשראי.
- בדיקות אוטומטיות: `node --test finance/*.test.mjs`.

## תפעול

לאחר הגדרת המפתח, רעננו את האתר, היכנסו למסך "יועץ AI" וודאו שמופיע חיבור פעיל. נסו "סכם לי את החודש". אם יש תקלה, חפשו את השגיאה בלוגים של ה-Edge Function ב-Supabase וודאו שלמפתח ה-API יש הרשאה ואמצעי חיוב או מכסה.
